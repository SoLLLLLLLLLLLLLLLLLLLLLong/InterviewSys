处理思路：
1. 先加 loading / 骨架屏 ：数据没回来之前先显示加载状态，避免白屏。

2. 加错误兜底 ：请求失败时显示错误提示页、重试按钮或空状态，而不是让页面直接报错。

3. 对返回数据做判空和默认值处理:避免接口返回 null、字段缺失时页面渲染报错。

4. 排查接口慢的原因 :看 Network 请求时间、接口耗时、返回体大小、是不是后端不稳定。

5. 加超时、重试或降级策略:比如请求超时后提示用户重试，或者先展示本地默认内容。

6. 日志和断点定位问题:看控制台报错、接口状态码、返回数据结构，判断是前端渲染问题还是后端接口问题。


如果面试官追问“白屏一般是什么原因”，常见有这几类：
1. 页面一上来就直接渲染接口数据，但数据还没回来
2. 接口返回字段和前端预期不一致
3. 某个字段是 null，前端直接取值报错
4. 请求太慢，没有 loading，用户就感觉是白屏
5. 请求失败后没有错误兜底
6. 资源太大或接口太慢，导致首屏等待时间过长

## 14. 页面交互一般怎么实现

### 简短回答

一般是通过控件事件和 `C#` 逻辑配合实现，比如按钮点击、输入框输入、页面跳转、数据刷新等。

### 稍微专业一点

页面上的交互通常会通过事件触发，比如点击按钮会触发点击事件，然后在 `C#` 代码里处理具体逻辑，比如请求接口、校验输入、刷新页面状态或者跳转到详情页。

## 15. 如果接口失败，一般怎么处理

### 完整回答

如果接口失败，我一般会先捕获异常，然后给用户展示错误提示，同时避免页面因为空数据直接报错。必要时还会加上默认值、重试机制或者空状态展示，让页面至少保持可用。

### 一句话回答

> 核心就是做异常捕获、错误提示和空值兜底，避免页面直接崩掉。

## 17. 面试官常见 Q&A

### Q1：.NET MAUI 是什么？

答：`.NET MAUI` 是微软推出的跨端 UI 开发框架，可以用一套技术栈开发多平台应用，比如 Android、iOS、Windows。

### Q2：你这个项目主要用什么语言？

答：主要是 `C#`，界面层通常会结合 `XAML` 来写页面结构和样式。

### Q3：XAML 是什么？

答：XAML 是一种界面描述语言，主要负责页面布局、控件结构和基础样式展示，可以类比成前端里的 HTML 加一部分声明式 UI 写法。

### Q4：C# 在项目里负责什么？

答：主要负责业务逻辑、接口调用、事件处理、数据解析和页面状态更新。

### Q5：你是怎么把后端数据显示到页面上的？

答：通过 `HttpClient` 请求后端接口，拿到 JSON 数据之后解析成对象，再通过数据绑定的方式展示到页面控件上。

### Q6：你觉得数据绑定的好处是什么？

答：它能让数据和页面展示建立关联，数据变化时页面会同步更新，代码会更清晰，也更适合做状态管理。

### Q7：这个项目为什么说是跨端？

答：因为 `.NET MAUI` 本身支持多平台开发，可以在较大程度上复用同一套页面和逻辑代码。

## 18. 【补充】.NET MAUI 可能被追问的知识点

### 1. MVVM 是什么？

MVVM 是一种常见的客户端界面开发模式，分为：

- `Model`：数据模型，例如接口返回的用户、列表项、详情对象。
- `View`：页面界面，一般是 XAML 页面。
- `ViewModel`：页面状态和业务逻辑，例如接口请求、按钮命令、列表数据。

面试表达：

> MVVM 的核心是把页面展示和业务逻辑拆开。View 负责界面，ViewModel 负责数据和逻辑，Model 负责数据结构。这样页面不会堆太多业务代码，也更方便维护和测试。

### 2. BindingContext 是什么？

`BindingContext` 可以理解为页面的数据上下文。XAML 页面里的绑定字段，会从 BindingContext 对应的对象里取值。

面试表达：

> 在 MAUI 里，页面控件通过 Binding 绑定数据，而 BindingContext 就是这些绑定数据的来源。比如把一个 ViewModel 设置成页面的 BindingContext，页面上的列表、文本、按钮状态就可以绑定到 ViewModel 的属性上。

### 3. ObservableCollection 是什么？

`ObservableCollection` 是 C# 里常用于列表绑定的数据集合。它的特点是集合变化时可以通知 UI 更新。

面试表达：

> 如果页面要展示列表，普通 List 更新后不一定自动通知页面刷新，而 ObservableCollection 增删元素时可以通知界面更新，所以在 MAUI、WPF 这类数据绑定场景里很常见。

### 4. MAUI 页面导航怎么理解？

页面导航就是从一个页面跳到另一个页面，例如从列表页进入详情页。

常见方式：

- Shell 路由导航：适合项目里统一管理页面路由。
- Navigation.PushAsync：把新页面压入导航栈。
- Navigation.PopAsync：返回上一个页面。

面试表达：

> 页面跳转可以理解为客户端里的路由。比如列表页点击某一项后，把 id 作为参数传到详情页，详情页再根据 id 请求接口或展示对应数据。

### 5. MAUI 里 async/await 用在哪里？

常见用于接口请求、文件读取、页面初始化等异步任务。

面试表达：

> 接口请求不能阻塞 UI 线程，所以一般会用 async/await。比如页面加载时异步请求后端数据，请求完成后再更新绑定数据源。如果请求失败，就捕获异常并展示错误提示。

### 6. MAUI 接口失败怎么处理？

处理思路：

- try/catch 捕获异常。
- 判断状态码和返回内容。
- 空数据给默认值或空状态。
- 超时或网络错误给重试提示。
- 页面不要因为 null 数据直接崩溃。

面试表达：

> 如果接口失败，我会先捕获异常，避免页面直接崩掉。然后根据状态码或异常类型提示用户，比如网络异常、服务错误、数据为空。页面展示上会加 loading、错误提示和空状态，保证体验稳定。

### 7. 【补充】.NET MAUI 和 Uniapp 有什么相似点和区别？

相似点：

- 都是跨端开发思路。
- 都可以复用一部分页面和业务逻辑。
- 都需要处理接口请求、页面跳转、数据展示和多端适配。

区别：

- Uniapp 基于 Vue 生态，更偏前端和小程序/H5/App 多端。
- .NET MAUI 基于 .NET 和 C#，更偏客户端跨端开发。
- Uniapp 页面通常用 Vue/模板语法，MAUI 页面通常用 XAML + C#。

面试表达：

> 我理解 Uniapp 和 MAUI 都是跨端开发方案，只是技术生态不同。Uniapp 更贴近 Vue 前端生态，MAUI 更贴近 C# 客户端生态。我之前做过 MAUI 页面和接口展示，所以对跨端页面、数据绑定、接口联调这些流程有实际经验；如果转 Uniapp，会重点迁移到 Vue 语法、页面生命周期和小程序 API 上。
